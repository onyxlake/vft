# Single-file web demo validation — 2026-11-11

The requested demo update uses English text and plain native controls. The build now emits
one `index.html`, with inline CSS/app code, an escaped JSON Worker bundle and base64 WASM.
The classic Blob Worker compiles WASM from bytes and retains bounded FileReaderSync reads.
No protocol, FEC, Rust dependency or minimum Rust version changed.

## Build and packaged recovery

Linux x64, Rust 1.99.1, Python 3.14.10 and Node 26.13.0:

- `cargo fmt --all`, `python scripts/check.py` and `git diff --check` pass.
- `cargo build --release --workspace` and `python scripts/check-web.py` pass.
- The release HTML is 108,320 bytes; SHA-256:
  `586a89b7dc91825c73128faeac272f5869ff09a6464a7cfe4deb525a7ef1dcc8`.
- Sixteen Python regressions include debug/release embedding, custom Cargo target directories,
  escaping Worker HTML delimiters, invalid bundle boundaries and preservation of unrelated files.
- The Node integration check executes the actual embedded Worker/bridge/WASM with a bounded
  FileReaderSync stand-in and no network APIs. Empty, 1 KiB, both-profile 1 MiB and balanced
  repair-only recovery pass with loss, duplicates and reorder. Each recovery independently
  compares bytes and SHA-256 with the original fixture through the native verifier.
- Maximum file reads remain at most 65,536 bytes. WASM linear memory is 1,310,720 bytes for
  robust/1 KiB cases and 1,507,328 bytes for balanced 1 MiB cases. These exclude process,
  JavaScript, File backing storage and Canvas memory.

Raw packaged recovery evidence: ignored `output/web-e2e-1794366895827/`.
The declared Rust 1.85 minimum was not rerun for this JavaScript/Python-only change;
earlier minimum-version evidence remains separate.

## Headless browser checks

Playwright 1.62.1 drove Chromium 156.0.8078.79 and Firefox 153.0 on Linux. Each browser
opened a copy of only `index.html` in an otherwise empty directory through `file://`, with
networking disabled. Both used the real Blob Worker, FileReaderSync and WASM, without browser
flags relaxing file-origin/CORS restrictions. HTTP startup also passed in both browsers.

- Balanced and robust each transmitted a 1,024-byte local fixture; the displayed digest
  matched independent SHA-256
  `55d4e7493d6c40f3bcead8ee5475594d242c7db59e45a0973ebcdf0737e5b05f`.
- Worker cell messages collected in each browser passed native render/sample/receiver
  verification and independent byte/hash comparison: two packets for balanced, three for robust.
  These are intercepted logical cells, not physical screen capture.
- Pause/resume retains the displayed frame and digest; Stop clears the frame and reenables
  settings. Stopping during preparation and restarting offline pass. Every created Worker
  terminates and every Blob URL is revoked on tested stop paths.
- Invalid fractional FPS is rejected. Profile changes restore the 8/16 px defaults.
- Fullscreen entry and programmatic exit pass. A 320×600 viewport pauses when the frame
  cannot fit, with no horizontal page overflow; enlarging and resuming works.
- Synthetic `visibilitychange` with hidden/visible state pauses without automatically resuming.
  This exercises the handler, not real desktop background-tab scheduling.
- At 1280×900, DPR 1, balanced uses a 960×540 Canvas and robust uses 1056×594; interpolation
  is disabled. At 1100×850, emulated DPR 1.25 and 2, balanced uses 1152×648 and 1536×864
  backing pixels respectively, with CSS dimensions equal to backing pixels divided by DPR.
- No page errors occurred. No external assets were requested for direct-file operation;
  Chromium reports the document and in-memory Blob URLs, while Firefox's request observer
  does not report these local loads. HTTP also made ordinary optional favicon requests.

Screenshots, the local browser harness, fixtures, collected cells and results are retained
under ignored `output/web-demo-checks/`; the complete passing matrix is `run-WBZWoG/`.
The initial smoke harness incorrectly counted in-memory Blob URLs as external requests;
the final harness distinguishes them. Firefox initially lacked a matching automation binary;
installing it under `.build/playwright/` allowed the matrix to run without project dependencies.

No actual unique capture FPS, CPU usage, whole-process memory, remote throughput or video
bitrate was measured. Safari, real monitor/zoom transitions, physical browser-to-native
capture, real hidden-tab scheduling and browser RDP acceptance remain unverified.
Native desktop harnesses were not rerun for this UI/packaging change. This does not advance M14.
