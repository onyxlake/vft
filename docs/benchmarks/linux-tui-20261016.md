# Linux Wayland TUI validation — 2026-10-16

The user requested real TUI testing on the existing Hyprland session. Native sender
and receiver ran in separate visible Kitty 0.49.2 windows with the independent
Wayland visual window and real ScreenCast/PipeWire capture. Automated terminal input
and Kitty's rendered-text snapshots exercised the terminal UI; physical keyboard
entry, mouse text selection and manual transcription were not measured.

The final 1 MiB transfer independently matches the source SHA-256. Two display issues
found during the first successful transfer are fixed in this checkpoint:

- Linux completion previously retained the last throttled progress snapshot, showing
  `Complete` beside partial recovered bytes and `Hash: Pending`. The adapter now
  publishes final verified bytes/hash and clears incomplete groups after verified
  output succeeds. The final output path is retained in scrollable result text.
- The shared request panel now displays the final success/failure result alongside
  the frozen code and says capture has ended. Returning from copy view therefore
  retains both the result/output path and request. Sender Escape and reopening its
  editor clear stale validation/preview notices.

These are presentation fixes. Packet/FEC/visual formats, file verification, resource
limits and create-new output semantics are unchanged. The pre-fix transfer already
passed independent file SHA verification; the stale display was not file corruption.
